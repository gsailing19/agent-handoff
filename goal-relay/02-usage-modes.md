# 02 — 三种使用方式

这份方法论有两种用法，取决于你现在处于什么阶段。

## 方式 A：方案已完成，让 Agent 拆（最常用）

你已经有了一份完整的设计方案（ADR、技术方案文档等）。把方案文档和 `03-goal-template.md` 一起给 Agent：

> "读 XXX方案.md 和 goal-relay-methodology/03-goal-template.md。按方法论把方案拆成 Goal 接力方案。包含每个 Goal 的可粘贴提示词、handoff 约定、验证命令。"

Agent 读完自动输出 Master Plan。80% 的情况都是这种方式——方案阶段不需要方法论介入，方案做完后才需要拆解执行。

## 方式 B：方案还没做，让 Agent 先消化方法再设计方案

你只有一个需求，还没有方案。先把方法论给 Agent：

> "读 goal-relay-methodology/ 下的文档。理解拆解约束。然后针对以下需求设计方案：[你的需求]。方案设计时要保证每个模块 800-1500 行、依赖单向、可拆成独立 Goal 执行。"

Agent 先内化"模块必须可拆、依赖必须单向、收尾必须独立"这些约束，再设计方案。这样产出的方案天然适合 Goal 接力——不需要后期再拆。

## 方式 C：手动接力（人在回路）

你已经有了完整的 Goal 拆分方案。但你不放心让 Agent 自动把所有 Goal 串行跑完——你想每个 Goal 跑完审查结果，确认方向没偏再放行下一步。

操作方式是用 master 对话做编排中枢：每步手动复制 Goal 提示词到新对话跑，跑完把总结贴回 master，master 审查后输出下一个 Goal。

> 完整步骤和操作流程见 `09-manual-relay-mode.md`。

## 怎么选

| 你现在的情况 | 用哪种 |
|------------|--------|
| 方案已经写好了，放心交给 Agent 自动拆 + 自动串行 | A |
| 还没方案，要 Agent 帮我设计 + 拆解一步到位 | B |
| 方案和拆分都有了，但想手动审查每一步再放行 | **C** |
| 方案是我自己写的（不用 Agent 设计），只需要拆 | A |
| 方案是我自己写的，拆好了，但想手动控制每步 | **C** |
