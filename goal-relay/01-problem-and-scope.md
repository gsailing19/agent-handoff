# 01 — 解决什么问题 + 适用范围

## 解决什么问题

AI 编程 Agent（Claude Code、Codex 等）的单个对话有两个天然约束：

1. **上下文退化**：对话窗口使用量超过 20-40% 后，Agent 会忘记早期的设计决策、混淆相似模块的差异、产出不一致的代码
2. **注意力分散**：1M 上下文不是塞更多东西的理由——注意力是稀缺资源，在几万行的对话历史中找关键信息会越来越慢

`/goal` 命令解决了"自动跨轮继续"的问题，但没有解决"上下文膨胀导致质量下降"的问题。

**Goal 接力工作法的核心思想**：把一个大型任务拆成 N 个独立的 Goal 会话，用结构化的 handoff 文档在会话之间传递上下文。每个 Goal 享有干净的对话窗口，同时不会丢失前序 Goal 的产出信息。

## 适用范围

| ✅ 适合 | ❌ 不适合 |
|---------|---------|
| 大型重构（改 15+ 文件，写 2000+ 行） | 单文件小改（不需要拆分） |
| 分阶段语言迁移（Python → Rust） | 调研探索（方向还没定，拆不动） |
| 先搭骨架再填内容的架构升级 | 偶发 bug 修复（无法拆成独立步骤） |
| 多个独立模块顺序实现 | 需要反复横跳调整的任务 |

## 支持 Agent

| Agent | /goal 支持 | 说明 |
|-------|-----------|------|
| **Claude Code** | ✅ 原生 | `/goal` 一级命令，配合 Haiku 评估器自动跨轮 |
| **Codex** | ✅ 原生 | `/goal` 的发源地，后移植到 Claude Code |
| Hermes Agent | ⚠️ 手动 | 支持 `--resume` 跨会话恢复，但需手动"继续" |
| OpenCode | ⚠️ 手动 | 无 /goal 等价，需手动循环 |

> 即使没有 `/goal`，方法论的核心机制（独立会话 + handoff 文档交接）仍然可用。
