# 07 — FAQ

### Q: 为什么不让一个 Agent 对话从头跑到尾？

跑是能跑完，但质量会递减。写到第 15 个 collector 时，Agent 可能已经忘了第 3 个 collector 用了什么特殊处理逻辑，产出不一致的代码。拆开能保证每个部分都在最佳状态下完成。

### Q: N 个 Goal 的开销不是更大吗（重新读文件、重新建上下文）？

是的，每个 Goal 要多花约 2000-5000 token 来加载上下文。但换来的是一致性和正确性——省掉了"定位因上下文退化导致的 bug"的时间，后者通常比加载上下文的开销大得多。

### Q: 如果 Goal 2 发现 Goal 1 的代码有问题？

Goal 2 的 Agent 在读 handoff 的 Section 6 时发现验证失败，应该先修再继续。但更理想的情况是：你在 Goal 1 结束后检查 git diff，发现不对就让 Agent 在 Goal 1 的对话中修好，然后再开 Goal 2。

### Q: `/goal` 和 `/plan` 有什么区别？什么时候用哪个？

`/plan` 是"只分析不动手"，用于设计阶段。`/goal` 是"动手 + 自动继续"，用于执行阶段。Goal 接力工作法属于执行阶段——在设计（Master Plan）已经完成后，用多个 `/goal` 会话分步实施。

### Q: 只有 Claude Code 能用吗？Codex 行不行？Hermes 呢？

原生支持 `/goal` 的 Agent：**Claude Code** 和 **Codex**。这两个开箱即用。

Hermes Agent、OpenCode 等没有 `/goal` 等价命令，但方法论的核心机制（独立会话 + handoff 文档交接）在任何 Agent 上都可用——只是每轮需要你手动说"继续"。

### Q: 可以用在非 Rust 项目吗？

可以。方法论的六个要素和拆解原则是语言无关的。Python、Go、TypeScript 项目都适用。

### Q: 每个 Goal 完成后，人检查 git diff 是什么意思？

花 30 秒看两件事：
1. 改动范围对不对——Goal 1 不应该碰前端代码
2. 有没有不该删的文件被删了

本质是个人工护栏，确认大方向没错。不是让你 review 代码细节。

### Q: handoff 文档和 Agent 的对话历史有什么区别？

对话历史会随着上下文窗口被压缩/裁剪。handoff 文档是写死在磁盘上的，不会被压缩。而且下游 Agent 读一个结构化的 400 字文档，比翻几万字的对话历史找关键信息快得多。
