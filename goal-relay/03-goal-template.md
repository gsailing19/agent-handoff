# 03 — Goal 提示词模板

> **给 AI 的指令**：用户让你同时读了一份方案文档和本文件。你的任务是：
> 1. 理解方案文档中的完整技术方案
> 2. **评估任务复杂度**：根据方案的代码量、文件数、任务类型多样性，判断需要几个 Goal
> 3. 按本文档的六要素模板，把方案拆成 N 个 Goal 接力方案
> 4. 输出一份完整的 Master Plan（含每个 Goal 的可粘贴提示词）到方案文档同目录下
> 5. 如果方案文档中没有指定输出路径，默认输出到 `{方案所在目录}/master-plan.md`
>
> ### 判断 N 的原则
>
> - 每个 Goal 产出 **800-1500 行**代码，太小没必要拆，太大上下文会退化
> - 每个 Goal 内任务**高度同质**——不要在一个 Goal 里同时写 collector 又改 Tauri 命令又删文件
> - **依赖单向**：Goal N 只依赖 Goal N-1，不反向
> - **最后一个 Goal 收尾**：删旧代码、改配置、全量编译验证
> - 如果拿不准，宁可多拆一个，不要少拆
>
> ### 常见规模参考
>
> | 方案规模 | 典型 N |
> |---------|--------|
> | 小（<2000 行，<15 文件，单一类型） | 2 个 Goal |
> | 中（2000-4000 行，15-30 文件，2 种类型） | 3 个 Goal |
> | 大（>4000 行，>30 文件，多种类型） | 4-5 个 Goal |
>
> **在 Master Plan 开头说明为什么拆成 N 个 Goal。**

---

这是最重要的文件。拆好方案后，每个 Goal 的提示词必须包含以下六要素。

## `/goal` 4000 字符限制

**`/goal` 命令的提示词不能超过 4000 字符。** 所以 Goal 提示词本身要极简——只给一句话任务 + 文件引用。具体内容靠 Claude 自己读文件获取。

**瘦身原则**：

| 要素 | 放 Goal 提示词里 | 放引用文件里 |
|------|:---:|:---:|
| 任务描述 | ✅ 一句话 | ❌ |
| 上下文/背景 | ❌ | ✅ 方案文档 |
| 文件引用路径 | ✅ | ❌ |
| 任务清单 | ❌ | ✅ 方案文档 |
| 完成条件 | ✅ 精简版 | ❌ |
| 验证命令 | ❌ | ✅ 方案文档 |
| 轮次上限 | ✅ 一个数字 | ❌ |

瘦身后的 Goal 提示词控制在 **500-1500 字符**，留足余量。

## 六要素

| # | 要素 | 为什么必要 | 示例 |
|---|------|-----------|------|
| 1 | **任务描述** | Agent 知道要做什么 | "实现 5 个 Tier 1 collector" |
| 2 | **开始前必读** | 给 Agent 完整的上下文入口 | "读 01-report.md + decisions/0008.md" |
| 3 | **任务清单** | 拆成可验证的子任务，防止遗漏 | "A. 加依赖 B. 定义类型 C. 实现 collector" |
| 4 | **完成条件** | Goal 评估器的判断依据，必须可机器验证 | "cargo check 退出码 0" |
| 5 | **验证步骤** | Agent 自己跑的命令，结果写 handoff | 具体的 bash 命令 |
| 6 | **轮次上限** | 成本失控的最后防线 | "最多 15 轮后停止" |

## 可复制模板（瘦身版，< 1500 字符，直接贴到 /goal）

```markdown
你是 {项目名} 的 {角色}。任务：{一句话}。

开始前读这些文件：
1. {方案文档路径}
2. {上一阶段 handoff 路径}（等 .done 后再读）

任务清单和约束见方案文档。核心约束：
- 不修改 {不碰的目录}
- {关键约束}

完成条件：
1. {条件 1，如 cargo check 退出码 0}
2. {条件 2}
3. 最多 {N} 轮后停止

完成后写 handoff 到 .claude/agent-handoffs/{session-id}/0X-{name}-report.md，touch .done。
```

## 旧版完整模板（供方案文档引用，不贴到 /goal）

以下模板用于写入方案文档的任务清单部分。Claude 执行 Goal 时自己读方案文档获取细节。

```markdown
你是 {项目名} 的 {角色}。

## 任务：{一句话描述}

### 背景
{2-3 句话说明上下文和这个 Goal 在整体中的位置}

### 开始前必读
1. {handoff 文件路径}（等 .done 文件存在后再读）
2. {设计文档路径}
3. {关键源文件路径}

### 任务清单
#### A. {子任务 A}
#### B. {子任务 B}
#### C. {子任务 C}

### 完成条件
1. {可验证的条件 1}
2. {可验证的条件 2}
3. 不要修改 {约束}
4. 最多 {N} 轮后停止

### 验证步骤（Goal 结束前执行）
\`\`\`bash
{具体的验证命令}
\`\`\`

### Goal 完成时必须做的事
1. 写 handoff 到 .claude/agent-handoffs/{session-id}/0X-{name}-report.md
2. touch .done
3. 在对话中输出 handoff 文件路径
```

## 写好完成条件的关键

条件必须能被对话记录验证。Agent 的评估器只看对话里有没有"我跑了命令 X，输出是 Y"。

```
✅ "cargo check 退出码为 0"       ← Agent 跑命令 → 输出进记录 → 评估器可判断
❌ "代码质量良好"                  ← 评估器无法判断什么叫"良好"
✅ "ls src/collectors/*.rs 显示 5 个文件"  ← 可数、可验证
❌ "所有 collector 实现完整"       ← 太模糊
```
