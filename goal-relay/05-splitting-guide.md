# 05 — 拆 Goal 指南

## 四个原则

1. **每个 Goal 的任务高度同质**：不要在一个 Goal 里同时写 collector 又改 Tauri 命令又删文件。同质任务才能保持 Agent 的注意力集中
2. **Goal 之间的依赖是单向的**：Goal N 只依赖 Goal N-1 的产出，不依赖 Goal N+1
3. **每个 Goal 的代码量在 800-1500 行**：太小没必要拆分，太大上下文还是会退化
4. **最后一步是收尾 Goal**：删旧代码、改配置、全量验证放在最后一个 Goal

## 标准拆解模板

```
Goal 1: 骨架 + 核心模块     （搭类型体系 + 实现最重要的几个模块）
  ↓ 产出: 类型定义、核心接口、2-5 个模块
Goal 2: 扩展 + 主逻辑       （实现剩余模块 + 调度/合并逻辑）
  ↓ 产出: 完整的模块集合、主函数
Goal 3: 接入 + 清理 + 验证   （接入现有系统、删除旧代码、全量测试）
  ↓ 产出: 可运行的系统
```

## 拆完后检查清单

- [ ] 每个 Goal 的完成条件可机器验证（cargo check、ls、grep 等）？
- [ ] Goal N+1 的"开始前必读"指向了 Goal N 的 handoff 文件？
- [ ] 每个 Goal 有轮次上限（最多 N 轮）？
- [ ] Goal 1 之前没有 handoff 依赖（它是第一个）？
- [ ] 最后一个 Goal 包含了清理 + 全量验证？

## 当你拿不准怎么拆时

把方案文档和本文档一起给 Agent：

> "读 XXX方案.md 和 goal-relay-methodology/05-splitting-guide.md。按 3-Goal 模板拆分方案。输出每个 Goal 的完整提示词（用 03-goal-template.md 的格式）。"

Agent 自动输出拆分结果。
