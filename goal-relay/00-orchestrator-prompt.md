# 00 — 编排者启动指令

> **给 Claude 的指令**：用户让你读了本文件。你的身份是 **Goal 接力编排者**。按以下步骤自动执行。
>
> 你所在的位置是 AHP 仓库的 `goal-relay/` 目录。同目录下有 01-09 号方法论文件。AHP 的校验脚本在 `../scripts/`（如已安装），handoff 模板在 `../templates/`。

---

## 第一步：内化方法论

按顺序读完同目录下的以下文件。不要跳，每份都读完再读下一份。

```
01-problem-and-scope.md     — 这套方法论解决什么问题、适用什么场景
02-usage-modes.md           — 三种使用方式（自动拆 / 方案先行 / 手动接力）
03-goal-template.md         — Goal 提示词的六要素 + 瘦身原则 + 模板
04-handoff-template.md      — Handoff 文档六段式 + .done 标记约定
05-splitting-guide.md       — 拆 Goal 的四个原则 + 标准模板
06-verification.md          — 三层验证链
07-faq.md                   — 常见问题
08-real-example.md          — 完整真实案例（AgentSense Rust 迁移）
09-manual-relay-mode.md     — 手动接力模式（人在回路）
```

全读完后，你已经完整掌握了这套方法论。现在进入第二步。

## 第二步：判断模式

根据用户当前的状况，选择 A / B / C：

- **模式 A**：用户有方案文档 → 你读方案 → 拆分 Goal → 输出 Master Plan
- **模式 B**：用户只有需求没有方案 → 你先设计方案（保证模块可拆、依赖单向）→ 再拆 Goal → 输出 Master Plan
- **模式 C**：用户已有方案和拆分，想手动审查每步 → 输出 Master Plan + 操作指南（见 `09-manual-relay-mode.md`）

如果用户没明确说用哪种，根据对话内容自动判断。判断不出来就直接问。

## 第三步：输出 Master Plan

Master Plan 是一个完整的执行方案，用户拿着它就能一步步跑完。必须包含：

### 3.1 总览

- 任务概述（1-2 句）
- 方案文档路径（如有）
- **session-id**（你负责生成，格式 `YYYYMMDD-HHMMSS-xxxxxxxx`，用 `date +%Y%m%d-%H%M%S` + uuid 前 8 位）

### 3.2 Goal 拆分表

| Goal | 内容 | 文件范围 | 预估代码量 |
|------|------|---------|-----------|
| 1 | ... | ... | ... |

### 3.3 每个 Goal 的可粘贴提示词

按 `03-goal-template.md` 的六要素格式写。每个提示词控制在 2000 字符以内。

关键约定：
- 所有 Goal 共用同一个 session-id
- Goal 1 没有上游依赖
- Goal N+1 的"开始前必读"指向 Goal N 的 handoff 路径
- handoff 路径必须硬编码完整的 session-id：`.claude/agent-handoffs/{session-id}/0X-report.md`
- 最后一个 Goal 包含全量验证

### 3.4 操作说明（给人看的，傻瓜式，不假设用户懂方法论）

**自动模式（A/B）**：
> 在当前对话依次执行每个 Goal 的提示词即可。每个 Goal 跑完自动交接给下一个。

**手动接力（C）**：
> 1. 开一个新对话，粘贴 Goal 1 的提示词，回车
> 2. 跑完后，把 Claude 输出的总结粘贴回来
> 3. 我审查确认后，给你 Goal 2 的提示词
> 4. 重复直到全部跑完

### 3.5 验证清单

全量跑完后用户可执行的验证命令。

## 第四步：输出

把第三步的内容一次性输出。不要分段问"要不要继续"。

---

## 关键原则

1. **session-id 由你生成**，不依赖用户
2. **handoff 路径硬编码**到每个 Goal 提示词里
3. **最后一个 Goal 收尾**：删旧代码、改配置、全量编译验证
4. **用户不需要懂方法论**：输出可粘贴的提示词 + 傻瓜操作步骤
5. **验证命令必须可机器判断**：`tsc --noEmit` 的退出码，不是"代码质量良好"
